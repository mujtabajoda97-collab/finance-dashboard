# مالي ومهامي — Personal Finance & Task Dashboard (PWA)

Next.js 15 (static export) · Tailwind CSS v4 · Supabase (Postgres + Auth + RLS) · Lucide Icons
عربي (RTL) / English (LTR) · Dark / Light · قابل للتثبيت على الهاتف كتطبيق.

## النسخة المنشورة

- التطبيق: https://finance-dashboard-chi-sage.vercel.app
- Supabase project: المشروع الجديد (`bkzs…emlfb`) — المشروع القديم `finance-dashboard` (`rhsq…ldxdqyo`) لم يعد مستخدماً
- Vercel project: `finance-dashboard`

## التشغيل خلال 5 دقائق

1. **قاعدة البيانات** — في Supabase → SQL Editor شغّل:
   - `supabase/migrations/0001_init.sql` (الجداول، الـ RLS، الـ Triggers، دوال التنبيهات)
   - `supabase/migrations/0002_cron.sql` *(اختياري)* — فعّل إضافة `pg_cron` أولاً من Database → Extensions.
2. **المتغيرات** — انسخ `.env.example` إلى `.env.local` وضع:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (المفتاح العام فقط — لا تضع service key أبداً)
3. **التشغيل**
   ```bash
   npm install
   npm run dev        # http://localhost:3000
   npm run build      # يُخرج موقعاً ثابتاً في out/
   ```
4. **النشر** — ارفع المشروع إلى Vercel / Netlify / Cloudflare Pages وأضف نفس المتغيرين. التثبيت كتطبيق (PWA) يعمل فقط على HTTPS.
5. في Supabase → Authentication → URL Configuration أضف رابط موقعك في **Site URL** حتى تعمل رسالة تأكيد البريد.

> للاستخدام الشخصي: بعد إنشاء حسابك يمكنك إيقاف التسجيل الجديد من Authentication → Providers → Email → *Allow new users to sign up*.

## ماذا يفعل الـ Schema تلقائياً (داخل قاعدة البيانات)

| الحدث | ما يحدث |
|---|---|
| إنشاء محفظة | الرصيد = الرصيد الافتتاحي |
| أي عملية (مصروف/دخل/تحويل) | يُحدَّث رصيد المحفظة فوراً عبر Trigger — لا يمكن للواجهة تعديل الرصيد يدوياً |
| نزول الرصيد تحت `min_balance_threshold` | يُسجَّل تنبيه `LOW_BALANCE` في `alert_logs` |
| تحويل للسودان | يُخصم المعادل بعملة المحفظة ويُثبَّت `exchange_rate_used` + `original_amount` + التاريخ |
| تعديل سعر الصرف | يُحفظ السعر الحالي + سجل تاريخي في `exchange_rate_history` |
| دفعة دين (`debt_payments`) | تُنشأ عملية في المحفظة (إيداع للمستحق لك / خصم لما عليك) ويُحدَّث `paid_amount` والحالة (OPEN → PARTIAL → PAID). لا يمكن تجاوز المتبقي. حذف الدفعة يعكس كل شيء |
| إكمال مهمة دورية | تُنشأ النسخة التالية تلقائياً (يومية/أسبوعية/شهرية) بموعد في المستقبل |
| `generate_due_alerts()` | مهام قادمة ضمن نافذة التذكير، مهام متأخرة (مرة كل 6 ساعات كحد أقصى عبر `last_notified_at`)، ديون تستحق خلال 3 أيام أو متأخرة |
| `generate_overdue_digest()` | ملخص صباحي/مسائي: «أنت لم تنفذ المهمة …، ويجب أن تبدأ بها الآن» |

كل الجداول محمية بـ RLS — كل مستخدم يرى بياناته فقط. دوال توليد التنبيهات لا يشغّلها إلا الـ service role (cron أو n8n).

## ربط التنبيهات بتليجرام / واتساب (n8n)

1. ضع `telegram_chat_id` أو `whatsapp_phone` في جدول `profiles` لحسابك.
2. في n8n أنشئ Workflow:
   - **Schedule Trigger** كل دقيقة.
   - **Supabase / HTTP Request** (بمفتاح service role، محفوظ داخل n8n فقط):
     `GET {SUPABASE_URL}/rest/v1/pending_alerts?select=*&order=created_at`
   - **Telegram → Send Message** إلى `telegram_chat_id` بنص `message`
     أو **Green API → sendMessage** إلى `whatsapp_phone`.
   - **HTTP PATCH** `alert_logs?id=eq.{id}` بالجسم `{ "is_sent": true, "sent_at": "now()" }`.
3. إن لم تفعّل `pg_cron`، أضف في نفس الـ Workflow استدعاءً كل 15 دقيقة لـ
   `POST {SUPABASE_URL}/rest/v1/rpc/generate_due_alerts`
   وآخر الساعة 8 صباحاً و8 مساءً لـ `rpc/generate_overdue_digest`.
